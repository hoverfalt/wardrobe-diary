## Findings: first run (16 October 2026, Claude Sonnet 5.5, each question asked once)

- **Raw data in the prompt: 7 of 30 correct (23 %).** With the whole log in the prompt (about 177,000 tokens per question), the model has to add up thousands of records by hand. It got 4 of 6 lookups and 3 of 11 metrics right, but none of the 13 questions where the precise definition matters. In 16 of its 23 misses it used up the 4,096-token answer limit without reaching an answer. The others were miscounts (407 wears instead of 408) or figures defined differently (turnover 371 % instead of 50 %; Sportswear named instead of Shirts as the most expensive category).
- **MCP tools: 29 of 30 correct (97 %), with less than a third of the tokens.** Most of the gain comes from governed computation. The server computes every figure with the app's own tested metrics, so the model doesn't have to re-derive definitions; it only has to pick the right tool and date range.
- **MCP tools plus the semantic layer: 30 of 30 correct (100 %), with about 4 % more tokens.** The single difference was "What was the cost per wear of the North Bend black vest in 2024?". Without the definitions, the model saw the lifetime figure of €0.05 but chose to divide the price by the 2024 wears instead (€0.26). With the semantic layer, it applied the definition: cost per wear is always a lifetime figure (decision D-2). This is exactly the kind of interpretation error the semantic layer is meant to prevent.
- **Caveats.** This is one run with one model. The difference between tools and tools plus semantics is a single question, so it is not statistically meaningful. The raw-data condition was held to the same 4,096-token answer limit as the others. Next steps: repeated runs (`--repeat`), a higher answer limit for raw data, and more questions where the tools leave interpretation to the model.
